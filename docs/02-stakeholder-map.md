## Stakeholder conflicts and tensions worth naming

- **Data ownership vs. project ambition:** BBS, BARC, and DAE are the real owners/stewards of the institutional data this project would need for a genuine deployment. This project has no relationship with any of them and should not imply otherwise anywhere in its documentation.
- **Field officer workload vs. tool adoption:** **ASSUMPTION** — a decision-support tool that adds steps to an already busy field officer's workflow is unlikely to be adopted regardless of its analytical quality. This project's capacity-building document (`docs/05-capacity-building.md`) treats this as a design constraint, not a solved problem.
- **National-level data vs. local relevance:** District-level statistics (the resolution most publicly available data supports, per the sources above) may not capture Upazila- or farm-level variation that actually drives a farmer's decision. This is a real, stated limitation of working at this data resolution.
